# wylde_check rules

`wylde_check` is Wylde's architectural linter. It runs once at end-of-task from both agent runtimes that drive Wylde development (Claude Code and the local Wylde harness) and is also callable directly via `wylde_check.run_all()` (full sweep) or `wylde_check.check_one_file(rel_path, content)` (per-file fast path). Findings are tagged ERROR, WARNING, or INFO.

### Invocation model

Both runtimes used to fire the architectural check **per write**:

- **Claude Code** ran `lint_hook.py` from the PostToolUse hook in `.claude/settings.json` after every Edit/Write/MultiEdit — a full 19-rule sweep against the tree each time.
- **Wylde harness** (`Core/harness/turn.py`) ran `prewrite.evaluate_prewrite` from inside `write_file.py` / `edit_file.py` before each write touched disk. ERROR findings blocked the write entirely (status `"blocked"`); the LLM had to recover mid-stream.

With 30 rules and Colossus-1 backend latency, the per-write cadence compounded badly on multi-edit tasks — a 200-edit task paid the full linter cost 200 times when only the final state mattered.

Both runtimes now fire the check **once per end-of-task**:

| Runtime | Trigger | What runs | What happens to findings |
| --- | --- | --- | --- |
| Claude Code | `Stop` event from `.claude/settings.json` → `lint_hook.py` | `wylde_check.run_all()` over the active tree | ERROR → exit 2 (Claude is forced to keep working until findings clear or the user intervenes); WARN-only or clean → exit 0 |
| Wylde harness | End of every chat turn in `_drive_turn_inner`, just before `turn_complete` fires | `wylde_check.check_one_file` over `state.files_written` (paths recorded by `write_file` / `edit_file` during the turn) | ERROR findings emitted as a single `tool_warning` event on `state.tool_events` with `source: "wylde_check_end_of_turn"`; per-file WARNINGs dropped (cross-file warnings still surface via `run_all()` at end-of-task) |

Same rules, same coverage, two different end-of-task triggers. The trade-off is the same on both sides: faster tasks, no per-write block, the agent learns about violations after the response is sealed rather than mid-stream. The old per-write block existed to stop the LLM from doubling down on a broken pattern across multiple writes; the equivalent guarantee at end-of-task comes from the agent re-reading its own warnings on the next turn.

The harness side targets only the files the turn touched (via the cheap `check_one_file` path) rather than re-sweeping the whole tree per turn — that would defeat the latency win. The full `run_all()` sweep belongs in end-of-task verification (Claude Code's `Stop` hook, the manual `python -c ...` invocation, or CI).

`force=True` no longer exists on `write_file` / `edit_file` — there's no per-write block to bypass.

### Severity & enforcement (Claude Code `Stop` mode)

- **ERROR** findings cause the hook to exit 2. On a `Stop` event, exit 2 prevents Claude from ending the turn and surfaces stderr back into the conversation — Claude is forced to address findings before the turn closes (or the user manually intervenes).
- **WARNING** findings print to stderr but the hook exits 0, so the turn ends normally.
- **No findings** → silent exit 0.

The `Stop` event does not support a `matcher` field, so the hook fires unconditionally on every turn boundary.

Manual invocation is still available: `python -c "from Core.harness.dev.wylde_check import run_all; print(run_all())"` or via the harness tool that wraps it. The `lint_hook.py` per-file mode is still callable for ad-hoc checks of a single file (`file_path` via stdin JSON, `$CLAUDE_FILE_PATH`, or argv[1]).

## Rules

1. **no_internal_http** — services don't use HTTP for internal IPC; named pipes are the contract. Gateway, the Ollama client, and the Memgraph Bolt driver are the documented exemptions.
2. **manifest_paths** — services with a daemon-managed `_start_X` must not also call `write_manifest()` from their own `run.py` (avoids the double-write the registry has to filter out).
3. **tool_id_regex** — every `tools/<group>/<id>/manifest.json` `id` and `name` matches `/^[a-z][a-z0-9_]*(?:\.[a-z][a-z0-9_]*)*$/`. Language-agnostic: only the manifest file is inspected, never the tool implementation.
4. **action_registry** — pipe-action names registered inside a single pipe module are unique (cross-module dupes like per-pipe `health` are fine).
5. **import_paths** — active code uses bare `Core.*` imports; the non-canonical `Wylde.Core.*` form is reserved for tests that need the try-fallback.
6. **dead_service_refs** — known-dead service names (renamed or removed during the Phase 9–12 refactor — former orchestrator/RAG pipes, the pre-merge security/web services, the dissolved voice assistant module, etc.) don't appear in active code. The canonical list lives in `DEAD_SERVICE_NAMES` inside `wylde_check.py`. An inline `# wylde-check: dead-ref-ok` marker suppresses a single line.
7. **inferencebar_purity** — _RETIRED (slice-11 cutover, 2026-05-29)._ Keyed on `InferenceBar.svelte`; the Svelte tree (`Core/GUI/src/`) was deleted at the cutover, leaving the rule no possible target. Removed from the dispatcher, module, and tests.
8. **gateway_scope** — every FastAPI route under `Gateway/routes/` starts with a documented prefix (egress, devices, link, push, voice, settings, system, rag, images, models, tools, health, mcp, extensions, `/__action__`).
9. **gui_action_contract** — _RETIRED (slice-11 cutover, 2026-05-29)._ Keyed on Svelte `pipeAction(SVC_X, …)` callsites under the deleted `Core/GUI/src/`. The gpui successor is rule 38 (`panel_verbs_exist_in_harness_registry`), which validates panel `pipe::call` / `stream_call` verbs against the live service registries. Removed from the dispatcher, module, and tests.
10. **gui_no_backend_bypass** — the gpui GUI panels + shell don't reference backend-owned storage paths (memory indexes, `data/` directories) or service `manifest.json` paths as literal strings — everything goes through a `wylde_gui_pipe` action. Repointed at the slice-11 cutover from the deleted Svelte `src/` + Tauri `src-tauri/src/` trees to the gpui Rust source under `Core/GUI/Frontend` + `Core/GUI/Shell`. The panel-registry aggregator under `Core/GUI/Manifest/` is out of scope — reading panel `manifest.json` files is its whole job.
11. **gui_pipe_constants** — _RETIRED (slice-11 cutover, 2026-05-29)._ Keyed on `SVC_X = "wylde-..."` JS constants in the deleted `Core/GUI/src/lib/api.js`. Subsumed by the gpui contract rules (38 `panel_verbs_exist_in_harness_registry`, 41 `rest_routes_exist_in_service`), which validate panel→service wiring directly. Removed from the dispatcher, module, and tests.
12. **tool_docstring_required** — every tool `manifest.json` under `**/tools/**` carries a non-empty `description` ≥20 chars. Post W1.5: the rule reads the manifest only (the old AST walk of Python tool files retired); the harness surfaces the description to the LLM as the tool's contract, and tools in any language pass as long as their manifest description is substantive.
13. **logging_setup_only** — only `Core/shared/logging_setup.configure_logging()` configures root logging in active code. Direct `logging.basicConfig()` / `logging.getLogger().addHandler()` / `.setLevel()` calls regress Phase 12's centralization. `Core/shared/logging_setup.py` itself and test files are exempt; docstring mentions inside `"""..."""` blocks are ignored.
14. **no_external_subprocess** — `subprocess.Popen` / `.run` / `.call` / `os.spawn*` are restricted to the Lifecycle daemon and a documented allowlist (tool runtimes wrapping external CLIs, Memgraph's Neo4j wrapper, VPN tunnel shell-outs, Voice's audio device manager). Other Wylde services route to peers through pipe actions, not subprocess.
15. **spawn_paths_exist** — every `python -m <module>` or script-path argument constructed inside `Core/Lifecycle/daemon_state.py` resolves to an importable module or existing file. Catches typos and renames that didn't propagate to the daemon.
16. **run_py_entry_point** — every top-level service folder uses exactly `run.py` as its entry point. No `<svc>_run.py`, `start_<x>.py`, `launcher*.py`, `main_*.py`, `server_*.py` variants are allowed alongside it. Service folders that are library-style (no entry point) are tolerated.
17. **pipe_name_convention** — every Windows named-pipe `wylde-<name>` literal in active code matches `^wylde-[a-z][a-z0-9-]*$` (lowercase, dash-separated). Underscore typos like `\\.\pipe\wylde_voice` are also flagged when they appear in a `pipe\…` path.
18. **run_py_startup_sequence** — each service self-attests the four-phase startup convention (`configure_logging` → `write_manifest` → `start_heartbeat` → `serve_loop`) by appending to the manifest's `startup_sequence` field as each helper fires. Post W1.7, the rule reads the manifest first; missing phases or out-of-order entries emit a warning. Services that haven't started yet fall back to the regex source-walk of their `run.py`. The attestation hooks live in `Core/shared/logging_setup.py`, `Core/shared/manifest.py`, and `Core/shared/ipc/_server.py` (with Rust mirrors in `wylde-shared`).
19. **shutdown_handler_marks_stopped** — services flip `shutdown_attested: true` in the manifest when `manifest.mark_stopped` (or its Rust mirror `ManifestWriter::mark_stopped`) fires. Post W1.8, the rule reads the manifest first: a manifest in the `stopped` state without `shutdown_attested = true` warns. Manifest-absent services fall back to a regex walk for SIGTERM/SIGINT/atexit registration plus a manifest-cleanup callsite.
20. **file_size_limit** — flat 700-LOC cap on every active Python file. No production/test split; the same rule applies everywhere. When a file blows the cap, the right move is almost always to split it along its natural seams (one rule per submodule, one route group per file, etc.). Counts raw lines including blanks and comments — file *length* is what hurts editing and review, not LOC density. A documented `_FILE_SIZE_QUEUED_SPLITS` allowlist inside the rule tracks the files that were already oversized when the rule landed; each entry has a one-line comment naming the planned split shape and the rule re-engages on a file once its entry is removed.
21. **test_init_present** — every `tests/` folder under an active root contains an `__init__.py`. Without it, pytest's rootdir discovery resolves sibling `tests/` directories by name and loads the wrong `conftest` — the same misroute that produced the bogus "passlib regression" miss-report.
22. **memory_layer_boundaries** — literal memory-layer storage paths (`memory/indexes/`, `memory/workspace_memories/`, `memory/long_term/`, `memory/short_term/`) only appear in code that lives inside the memory layer (`Core/harness/memory/`). Other callers route through the corresponding `memory.*` pipe action on wylde-harness instead of touching the on-disk state.
23. **action_docstring_required** — every registered pipe-action handler function carries a non-empty docstring (≥15 chars). Handlers are the contract surface the LLM sees via `tools.list` / pipe introspection; missing docstrings ship a black-box action. Handlers are discovered through the canonical `register_action(...)` callsites and `_ACTIONS = {...}` dicts in each pipe module.
24. **no_bare_except** — bare `except:` is always flagged. `except Exception:` is flagged only when the handler body has multiple statements AND neither logs (`logger.exception/.error/.warning/.warn/.critical/.info/.debug`) nor re-raises nor references the bound exception (`as exc`). Single-statement recovery (`pass`, `return <fallback>`, `x = {}`, nested fallback `try:`) is the canonical intentional best-effort shape and is allowed. Specific exception classes (`FileNotFoundError`, `ValueError`, …) are deliberate handling and allowed. Tests exempt. Two inline suppressions are honoured: ruff's existing `# noqa: BLE001` marker, and the rule-specific `# wylde-check: bare-except-ok`.
25. **service_owns_its_state** — a service only reads/writes paths inside its own data directory; cross-service state access goes through the peer's pipe action, not the filesystem. `Core/Lifecycle/` (the daemon) and `Core/shared/` are unrestricted; the GUI surface is covered by rule 10 instead of double-flagging here. A small documented exemption list in the rule body covers files that legitimately straddle two services as a hand-off placeholder (the entry must reference a punch-list item in its module docstring so the rewire is tracked).
26. **import_paths_rust** — Rust crates may only depend on each other via `wylde-shared`. Any `use wylde_<other_crate>::` outside the crate's own name (with `wylde_shared` always allowed) is flagged. Deep `super::super::` traversal is also flagged as a sign the module graph is wrong — by the time you need to walk three module levels up, the file belongs somewhere else. Walks `rust/crates/*/src/**/*.rs`; integration tests under `rust/crates/*/tests/` are exempt.
27. **no_silent_error_swallow_rust** — `let _ = <result>;` and trailing `.ok();` patterns that drop a Result without logging are flagged. The `let _` heuristic uses an allowlist of known-Result-returning expressions (`atomic_write`, `fs::*`, `.send(`, `.spawn(`, etc.) and a small known-not-Result allowlist (`tokio::spawn`, `Vec::new`, `Arc::clone`, …) to keep false positives down. An inline `// wylde-check: discard-result-ok` marker suppresses a deliberate discard (typical for shutdown paths where logging the error would itself fail).
28. **logging_setup_only_rust** — only `wylde_shared::logging::configure_logging` may build or initialise the tracing subscriber. Direct `tracing_subscriber::fmt()`, `tracing_subscriber::registry()`, and `tracing::subscriber::set_global_default` calls are flagged everywhere except `wylde-shared/src/logging.rs` (the source of truth). Mirrors rule 13 on the Python side.
29. **no_external_process_spawn_rust** — `std::process::Command::new`, `tokio::process::Command::new`, and bare `Command::new` are restricted to the `wylde-lifecycle` crate. Supervising other processes is the lifecycle daemon's job, not a per-service responsibility. Mirrors rule 14 on the Python side.
30. **gui_error_reporting** — _RETIRED (slice-11 cutover, 2026-05-29)._ Keyed on Svelte `console.error` / `toast.error` / `alert` sinks + swallowed `catch` blocks under the deleted `Core/GUI/src/`. The gpui panels surface errors as `Result`-typed panel state rendered inline, a structurally different model with no `console.error` analogue — a gpui-era error-reporting rule is a possible post-alpha addition. Removed from the dispatcher, module, and tests.
31. **shutdown_reaps_manifest_orphans** — `stop_all_daemon_managed` in `Core/Lifecycle/daemon_state/__init__.py` (the function both the SIGINT/SIGTERM handler and the `service.shutdown_all` pipe action share) must invoke a function whose name matches `reap*orphan*`. Why: the tracked-Popen teardown only knows about services this daemon spawned this session; a process orphaned by a prior daemon crash has `_<service>_proc = None` on the fresh daemon, so the matching `_stop_<service>` short-circuits and the orphan keeps its pid + pipe binding across every restart. The periodic `sweep_orphans` only marks manifests whose pid is *dead*, so a *live* orphan stays invisible. A manifest-walking reaper is the only safety net that closes the loop — the rule is name-pattern-bound rather than name-specific so the reaper can be renamed (`reap_manifest_orphans`, `_reap_live_orphans`, etc.) without churn here, but rejects unrelated calls so it can't silently regress.
32. **manifest_sandbox_required** — tests under `Core/Lifecycle/tests/` and `Core/harness/tests/` that touch the manifest layer must rebind `_MANIFEST_DIR` to a tmp path (either via `monkeypatch.setattr` in the test itself, or via an autouse fixture in a sibling `conftest.py`). An unsandboxed test can trip the orphan reaper from rule 31 into killing real wylde services — caught + fixed during the Phase 11.B soak.
33. **no_cross_panel_imports** — every `Core/GUI/Frontend/Panels/*/Cargo.toml` may only depend on the shared-infrastructure crates (`wylde-theme`, `wylde-gui-pipe`, `wylde-gpui-input`, `wylde-panel-registry`). Any other `wylde-panel-*` dep is a panel-to-panel import that would couple two first-party panels at compile time; any other `wylde-*` crate is the panel reaching for backend internals instead of going through `wylde-gui-pipe`. Cross-panel state belongs on `wylde-gui-pipe::nav_bus` or in `wylde-panel-registry`.
34. **no_legacy_gui_imports_in_panels** — no `tauri::*` use paths and no Svelte references (`.svelte` extension, `svelte::`, `"svelte"` import literal) anywhere under `Core/GUI/Frontend/Panels/**`. Panel crates are gpui-native; the legacy Tauri+Svelte tree at `Core/GUI/src/` + `Core/GUI/src-tauri/` was deleted at the slice-11 cutover (2026-05-29). The rule remains relevant — it stops a panel from reintroducing a `tauri::`/Svelte dependency — and strips comments first so historical references in module docs don't false-fire.
35. **webview_only_in_extension_handlers** — `wry::*` imports are reserved for `Core/GUI/Frontend/Extension_handlers/WebView/**`. The Shell legitimately renders iframe slots, but only through `wylde_webview::IframeHost` / `wylde_webview::probe_url` — never by reaching for `wry` directly. The rule guards against a first-party panel embedding a browser engine instead of rendering native gpui.
36. **first_party_manifest_must_be_gpui_view** — two symmetric kind-must-match-origin checks. First-party manifests under `Core/GUI/Frontend/Panels/**` declare `source.kind: "gpui_view"` for every entry in their `panels` array; the `iframe` shape is reserved for extensions. AND extension manifests under `Extensions/<X>/` (canonical `manifest.json`, `mcp-server.json`, or `mcp-client.json`) that carry a `ui_panels` array declare `source.kind: "iframe"` for every entry — extensions can't ship native gpui Views (no shared gpui dep, no factory-registration path), so a `gpui_view` declaration there is statically impossible. Both checks live in the same rule because they enforce the same invariant from two sides.
37. **panel_crate_must_be_workspace_member** — every `Core/GUI/Frontend/Panels/*/Cargo.toml` that exists on disk appears in the `members = [...]` array of `Core/GUI/Cargo.toml`, AND every `Frontend/Panels/*` entry in `members` resolves to a real `Cargo.toml` on disk. Either-direction failure either skips the crate at build time or makes `cargo metadata` refuse the workspace; the rule catches both at the architecture layer so the failure surfaces at lint time, not at the first compile.
38. **panel_verbs_exist_in_harness_registry** — for every `wylde_gui_pipe::call(SVC, "POST", "/__action__", json!({"action": "X", ...}))` and every `wylde_gui_pipe::stream_call(SVC, "X", ...)` in `Core/GUI/Frontend/Panels/*/src/ipc.rs` whose first arg resolves to a registry-indexed service, the named verb `X` must appear in that service's registry. Indexed services today: `wylde-harness` (union of Rust `ALL_PIPE_ACTIONS` and Python `_ACTIONS`), `wylde-extension-bridge` / `wylde-ollama` / `wylde-voice` (each crate's `const ALL_ACTIONS: [&str; N] = [...]`). Catches typo'd verbs and as-yet-unimplemented surfaces at edit time instead of as a runtime `no_action` error. Calls to services without a discoverable registry (`wylde-vpn`, `wylde-gateway`'s REST surface) are intentionally skipped — the Gateway HTTP surface lives in rule 41 instead. Dynamic-action call sites (where the action key is a parameter) are skipped too. Fix is to add the verb to the service, fix the typo, or remove the call.
39. **nav_targets_exist** — every literal-string `request_nav("X")` / `nav_bus::request_nav("X")` / `wylde_gui_pipe::request_nav("X")` call under `Core/GUI/**/*.rs` (excluding the legacy Tauri+Svelte tree and the `nav_bus.rs` source itself) must resolve to a panel actually declared by some `manifest.json` under `Core/GUI/Frontend/Panels/**`. The runtime nav bus silently absorbs unknown keys (`request_nav` returns `false`), so an unknown target shows up as a no-op the user can't debug; this rule forces the panel manifests and the nav callsites to stay in sync. Constant-propagation: `request_nav(IDENT)` where the file declares `[pub] const IDENT: &str = "core/foo"` resolves through the file-local constant map and is checked the same as a literal. Variable-argument call sites whose value isn't a const string are intentionally skipped — runtime-built keys aren't statically checkable.
40. **required_services_includes_called_services** — under-declaration (ERROR) and over-declaration (WARNING). Under-declared: a service called from a panel's `src/ipc.rs` that isn't in `required_services`; the Shell's ServiceUnavailable stub won't fire when that service is down, leaving the panel rendering a broken half-state. Over-declared: a service listed in `required_services` that the panel doesn't actually call; the panel grays out unnecessarily when that service is down even though it would still work. Calls whose service arg can't be statically resolved (parameter-passed) are skipped; both literal `"wylde-foo"` and `pub const SVC_X: &str = "..."` indirection are supported. Panels whose docstring-documented design is "render degraded cards instead of the ServiceUnavailable stub" can opt out by adding `"wylde_check_opt_outs": ["required_services_includes_called_services"]` at the manifest's top level — used today by the Dashboard panel (every card soft-fails independently).
41. **rest_routes_exist_in_service** — every literal-shape `wylde_gui_pipe::call(SVC, "METHOD", "/api/...", ...)` from a panel must match a route declared in the destination service's axum routing table. Indexed services today: `wylde-gateway` only (every other panel-callable service routes via action envelope, covered by rule 38). Path parameters match panel-side wildcards: an axum route `/api/images/library/:img_id` matches a panel call `/api/images/library/{id}` (single-segment wildcard). Method must match exactly; `Router::nest()` isn't currently followed (no panel routes use nesting today). Documented limitation: calls whose method or path arg isn't a literal — including helpers that accept `path: &str` and forward to `pipe::call` — are intentionally skipped. The rule trades narrow scope for low false-positive rate; if a helper forwards opaquely, follow the rule's spirit by checking the route by hand. Action-envelope calls (`POST /__action__`) are skipped — they're rule 38's surface.
42. **manifest_factory_resolves** — every first-party panel `manifest.json`'s `source.factory` string must resolve to a real `pub fn` in a real workspace-member crate. Format: `<crate_underscores>::<Type>::<fn>` or `<crate_underscores>::<fn>`. The crate name is matched against the canonical `name` field of every workspace member's `Cargo.toml` (after `-` → `_` normalisation); the function name is grepped as `pub fn <name>(` (or `pub async fn`, `pub(crate) fn`, etc.) anywhere under the crate's `src/`. Intermediate `Type::` segments are accepted but not verified — they're enforced at build time when the aggregator calls into the factory. Catches deleted/renamed factory entry points at edit time so the aggregator doesn't blow up at build with an opaque link error.
43. **stream_call_must_handle_cancel** — every `wylde_gui_pipe::stream_call(...)` invocation under `Core/GUI/Frontend/Panels/**` must retain the returned `PipeStream`. Safe shapes: `let stream = stream_call(...)`, `self.stream = Some(stream_call(...))`, `stream_call(...)?`, `stream_call(...).await?`, `return stream_call(...);`, and trailing-expression position (the call is the block's value, no terminating `;`). Flagged shapes: `let _ = stream_call(...)` (explicit discard) and bare `stream_call(...);` expression-statement (anonymous discard). When the discard is genuinely intentional (e.g. a fire-and-forget probe at shutdown), annotate the call site with `// wylde-check: stream-discard-ok` on the same line or the line directly above. Heuristic limitation: helpers that wrap `stream_call` and return the result without binding are accepted (trailing-expression detection); helpers that accept a `PipeStream` parameter and return it without naming the original `stream_call` site are out of scope.
44. **launcher_enumerates_services_from_manifests** — the launcher (`Core/Lifecycle/launcher.py`) builds its service set from the filesystem-as-registry (`Network/services.yaml` + per-service `manifest.json`), never a hardcoded roster. Two-pronged on the Python launcher: it must reference a manifest/registry loader (`load_services` / `load_manifest` / `list_service_folders`) AND must not assign a module-level UPPERCASE `SERVICES` list literal (case-sensitive, so the everyday `services = load_services()` local never matches). The Rust lifecycle crate (`rust/crates/wylde-lifecycle/`) is held to the negative half only — its tier=core `start_<name>` sequence is bespoke, documented bring-up by design (Memgraph forks a JVM, the harness can run in-process, several services flip Python⇄Rust on a per-service env var, and the order encodes hard runtime deps), but a hardcoded `const SERVICES: [&str; N]` roster *is* flagged. Added at the slice-11 cutover; enforces the Wylde user's modularity directive that launcher rules cover all services via the manifests.
45. **shutdown_enumerates_services_from_manifests** — `Core/Lifecycle/shutdown.py::shutdown_all` (the canonical drain the GUI reaches via `lifecycle.shutdown_all`) orders teardown from the running set + manifest `shutdown_order` (reverse-launch / reverse-topo by default, per-service override), not a hardcoded list: it must reference the running-set / manifest enumeration (`get_running` / `_shutdown_sequence` / `load_manifest` / `shutdown_order`) and carry no `SERVICES` literal. The gpui-side `Core/GUI/Shell/src/shutdown.rs` must *delegate* to that drain by dispatching `lifecycle.shutdown_all`; its `WYLDE_SERVICE_PROCESSES` / `WYLDE_KILL_TARGETS` constants are the recognised hard-kill image-name fallback (a last resort for `taskkill`, not the service enumeration) and are deliberately NOT treated as a roster. Added at the slice-11 cutover.
46. **every_service_has_manifest** — bidirectional service↔manifest coverage at the launcher's top-level discovery domain. Forward: a top-level folder that follows the entry-point convention (has a `run.py`) must carry a `manifest.json` so the launcher can discover, order, and shut it down. Reverse: a runtime/archive dir (`data` / `logs` / `docs`) must NOT carry a service manifest — an auto-gen stub there (the launcher would try to register it) is the bug this catches. `Core` is exempt: its `Core/manifest.json` is a legitimate infra rollup, not a service stub. Added at the slice-11 cutover (which deleted the stale `logs/manifest.json` the reverse check now guards).
47. **service_manifest_schema** — every top-level service `manifest.json` declares the required keys with correct types: `name` (non-empty string), `entry_point` (key present; string or null — the canonical launch command / binary, null for an in-process/library/pipe-only service; there is no separate `binary` key), and `shutdown_order` (integer). Optional keys are type-checked when present: `depends_on` (list), `health_check` (null / string / object — shapes `"pipe:wylde-<name>"` or an `http(s)://` URL the launcher gates the next spawn on), `tier` (string). The `shutdown_order` + `health_check` fields were added to `Core/Lifecycle/manifest.py`'s `DEFAULT_MANIFEST` at the slice-11 cutover, so newly auto-generated and additively-merged manifests satisfy the rule automatically. Added at the slice-11 cutover.
48. **gateway_verbs_exist_in_harness_registry** — the outbound companion to rule 38. Rule 38 covers the **GUI → harness** edge (panel `pipe::call` / `stream_call` verbs); this rule covers the **Gateway → harness** edge. Every harness-pipe verb a Gateway REST handler dispatches — `harness_dispatch("verb", payload)` (the `routes/common.rs` helper, service implicitly `wylde-harness`) or `pipe_action(SVC, "verb", payload)` where `SVC` resolves to `"wylde-harness"` — must appear in the harness pipe registry, defined identically to rule 38 as the **union of** the Rust `ALL_PIPE_ACTIONS` array (`rust/crates/wylde-harness/src/pipe.rs`) **and** the Python `_ACTIONS` dict (`Core/harness/pipe/__init__.py`). That union is what an over-the-wire dispatch actually reaches: the Rust harness serves the ported verbs and surfaces the rest as `no_action` for the Python strangler-fig's in-process fallback, so a verb on *either* side is reachable. (This is why the singular workspace-memory CRUD verbs `memory.workspace.*` — served only by Python — are valid Gateway dispatches even though the Rust registry holds only the plural workspace-registry verbs `memory.workspaces.*`; the two are distinct surfaces, not a typo.) Walks `rust/crates/wylde-gateway/src/**/*.rs`. An unregistered verb is a latent runtime `no_action` on that REST route, caught here at edit time. Dispatches whose verb isn't a static string literal (e.g. the MCP adapter's parameter pass-through) are skipped. A deliberate optimistic probe of an *optional* verb (one the handler tolerates `no_action` from, falling back to another path — e.g. `tools.get` falling back to `tools.list`) opts out with an inline `// wylde-check: optional-verb` marker on the call line or the line directly above. Added at the 2026-05-30 codebase-audit slice. (Numbering: the suite's labels already reached 47 with rules 7/9/11/30 retired, so 48 is the next free number; this brings the active count to 44.)
49. **no_python_gateway_imports** — no active `.py` file may import the deleted top-level `Gateway` package. The Python FastAPI Gateway was deleted on 2026-05-30 (the Rust `wylde-gateway` crate is the live server) and the three in-process client libraries that had kept the folder on disk moved into `Core/shared/`: `Gateway/client.py` → `Core/shared/egress_client.py`, `Gateway/auth/` (device-token subset) → `Core/shared/gateway_auth/`, `Gateway/extension_routes.py` → `Core/shared/extension_routes.py`. Any surviving `from [Wylde.]Gateway … import` or `import [Wylde.]Gateway` is a latent `ImportError` and a sign code is reaching for the deleted shell instead of the relocated library. Two matchers are used, both requiring real import syntax (the `import` keyword for the `from` form; end-of-line / `as` for the bare form) so a docstring line that merely begins "from Gateway …" can't false-fire, and a longer identifier like `GatewayHelper` isn't matched (word boundary after `Gateway`). The `wylde_check` package and its tests are skipped — they carry the pattern as fixture / documentation data. ERROR severity. ## Severity & inline suppressions

Severities are advisory at the rule level — what each agent runtime does with them is described in *Invocation model* above. Rule 6 (`dead_service_refs`) honors an inline `# wylde-check: dead-ref-ok` marker for lines that intentionally name a dead service (e.g. migration docs). Rule 27 (`no_silent_error_swallow_rust`) honors `// wylde-check: discard-result-ok` for deliberate Result discards on shutdown paths. Rule 43 (`stream_call_must_handle_cancel`) honors `// wylde-check: stream-discard-ok` for legitimate fire-and-forget streaming probes. Rule 48 (`gateway_verbs_exist_in_harness_registry`) honors `// wylde-check: optional-verb` for a deliberate Gateway probe of an optional harness verb that tolerates `no_action`.

Neither runtime blocks writes per-call anymore, so there is no per-tool `force` bypass. To suppress a specific finding, either fix the underlying issue, add the documented inline marker (rule 6 only), or extend the rule's exemption set in `Core/harness/dev/wylde_check/rules/` if the case is genuinely out-of-scope.

## Where the rule code lives

Rules live under `Core/harness/dev/wylde_check/rules/` as `check_<rule_name>` functions returning lists of `Finding` objects. The package's `run_all()` dispatcher aggregates them and returns the standard `{ok, data: {findings, summary}}` envelope; `check_one_file(rel_path, content)` runs the per-file subset (the cheap rules that don't need cross-file state) and is what the harness end-of-turn check calls.

### 50. `no_bare_tokio_in_panel_src`

**Severity:** error

**Scope:** `Core/GUI/Frontend/Panels/*/src/**/*.rs`

**What it catches:** bare tokio primitives reached from first-party gpui panel code — `tokio::spawn(`, `tokio::time::sleep(` / `sleep_until(` / `interval(` / `timeout(`, `tokio::task::spawn(` / `spawn_blocking(` / `spawn_local(`, and direct runtime construction (`Runtime::new(` / `Builder::new_*().build(`).

**Why:** gpui runs on its own executor, not a tokio runtime, so any bare tokio spawner/timer/runtime call reached from a panel panics at startup with *"there is no reactor running, must be called from the context of a Tokio 1.x runtime"*. This actually fired at `Core/GUI/Frontend/Panels/Chat/src/chat_panel.rs:544` (the consent-reconnect backoff loop added in the 10/10 polish slice). Unit tests missed it because `#[tokio::test]` provides a runtime; production gpui doesn't.

**Fix:** drive async work through the gpui executor — `cx.spawn`, `cx.background_executor().spawn`, `cx.foreground_executor().spawn`, `cx.background_executor().timer()`.

**Allowed (not flagged):** call sites inside a `#[cfg(test)]` module or `#[tokio::test]` fn; inside a `#[tokio::main]` fn; provably inside an `if Handle::try_current().is_ok() { ... }` guard; `use` import lines; matches inside `//` / `///` / `/* ... */` comments; or a line carrying the explicit opt-out `// wylde-check: tokio-runtime-provided` (same line or the line above).

### 51. `no_panic_in_panel_render`

**Severity:** error

**Scope:** `Core/GUI/Frontend/Panels/*/src/**/*.rs`

**What it catches:** panic primitives reached from first-party gpui panel code — `.unwrap()`, `.expect(...)`, `unwrap_or_panic!`, `unreachable!`, `unimplemented!`, `todo!`, and bare `panic!(`.

**Why:** panels are the most user-visible layer and the closest thing Wylde has to "live rendering"; a panic in a panel takes down the *entire* gpui shell because every panel shares the one event loop. This actually fired at `Core/GUI/Frontend/Panels/Dashboard/src/lib.rs`: two `snapshot.gpus.first().unwrap()` calls in the render path panicked at startup (`called Option::unwrap() on a None value`, process exit code 101) because on a cold start the VRAM broker's inventory hasn't landed yet, so `gpus` is empty. The window never became visible. Unit tests missed it because the test paths feed populated inventories; production cold-start does not.

**Fix:** use `.unwrap_or(default)`, `.unwrap_or_else(|| …)`, `if let Some(x) = …`, `match`, the `?` operator (in fallible contexts), or surface a fallback render value like `"—"` — the convention the Dashboard panel already uses for an absent `active_model`.

**Allowed (not flagged):** call sites inside a `#[cfg(test)]` / `#[tokio::test]` / `#[test]` block; inside a `const` / `static` item (compile-time — a const initializer that "panics" is a build error, not a runtime crash); matches inside `//` / `///` / `/* ... */` comments; matches inside string / raw-string literals (error messages that merely *mention* "unwrap"/"panic" are fine); or a line carrying the explicit opt-out `// wylde-check: panel-panic-allowed` (same line or the line above).

**Opt-out must be justified:** the opt-out is meant to be *rare* — used only where panicking is genuinely the right behaviour (e.g. a struct invariant the type system can't express). When the marker is used, a `// SAFETY:` or `// INVARIANT:` comment explaining why panicking is OK must sit in the same small window (the flagged line, the line above, or two above). An opt-out marker *without* that justification is itself a violation, flagged with a pointed message rather than silently honoured.

### 52. `silent_skip_in_service_start`

**Severity:** error

**Scope:** `rust/crates/wylde-lifecycle/src/state/services.rs`

**What it catches:** any `return Ok(())` / `return Ok(<expr>)` inside a function whose name matches `start_[a-z_]+` whose enclosing brace-block carries no preceding `tracing::` call. In other words: if `start_<service>` returns `Ok` but didn't spawn anything, the daemon's log must say WHY — one line per skip.

**Why:** every per-service `start_<service>()` opens with guards like `if is_service_alive(...) { return Ok(()); }`, `if nospawn_enabled() { … }`, `lang == Python`, `rust_binary_path() == None`. When a service is killed ungracefully (Ctrl-C / taskkill / SIGKILL) its manifest stays on disk marking it "alive" with a now-dead pid; a guard that returns `Ok` *silently* then skips the spawn with nothing in the log. On 2026-05-31 this left the harness, extension_bridge, ollama, trainer_worker and trainer all dark — Dashboard all-red — and the Wylde user could only recover by hand-wiping `data/manifests/`. The boot orphan-sweep (in `daemon.rs`) now self-heals the stale state, and this rule pins the companion guarantee: no spawn is ever skipped silently. The diagnostic the fix adds — `"{name}: already alive (manifest pid={pid}); skipping spawn"` — is exactly what was missing.

**Fix:** add a `tracing::info!` / `tracing::warn!` in the early-return branch explaining the skip (the already-alive guard logs the manifest pid so the operator can see which dead process the daemon believed owned the slot).

**Allowed (not flagged):** the successful-spawn tail of a function (a bare `Ok(())` *expression* after `record_spawn(...)` / a `match` arm — it has no `return` keyword, so it's never matched); `return Ok` in any non-`start_*` function (e.g. the shared `stop_service` helper); a `return Ok` whose block already carries a `tracing::` call before it; matches inside `//` / `///` / `/* … */` comments or string / raw-string literals; or a line carrying the explicit opt-out `// wylde-check: silent-skip-allowed` (same line or the line above — meant to be rare).

### 54. `no_unbounded_log_sink_rust`

**Severity:** error

**Scope:** `rust/crates/*/src/**/*.rs`, skipping the canonical rotation factory `rust/crates/wylde-shared/src/logging.rs`.

**What it catches:** a raw append-only file open — `OpenOptions::new()….append(true)` (both `std::fs` and `tokio::fs`) — anywhere outside the logging factory. That is the tell-tale of an ad-hoc log sink that reaches disk without inheriting the shared size + retention policy.

**Why:** before the 0.2 Stability audit (finding C, #98) there was no log rotation anywhere in the product. Every persistent sink — `ipc.jsonl`, the gateway `gateway.jsonl` / `egress.jsonl` audit logs, `gui_errors.jsonl`, the `neo4j.log` console redirect — was opened `create(true).append(true)` with no size and no age cap. `ipc.jsonl` alone had grown to ~179 MB (+~179 MB/month, per user, forever). The failure is pure silent disk growth: no crash, hidden until a user's disk fills. The structural fix routes every Wylde-owned sink through `wylde_shared::logging::RotatingLog` (via `rotating_sink`) or `open_rotating_append`, which caps each file at `WYLDE_LOG_MAX_BYTES` (default 10 MiB) and keeps `WYLDE_LOG_KEEP_FILES` (default 5) rotated generations — bounding any sink at ~60 MB. This rule pins the guarantee: a future service that opens a log the ad-hoc way turns the gate red instead of leaking, so bounded-ness is inherited by construction rather than remembered file-by-file.

**Fix:** route the log through `wylde_shared::logging::rotating_sink(path).write_line(line)` (buffered append + flush, rotation on size), or — for a subprocess stdout/stderr redirect that needs a raw file handle — `wylde_shared::logging::open_rotating_append(path, RotationPolicy::from_env())`.

**Allowed (not flagged):** the canonical factory file itself (`wylde-shared/src/logging.rs`, which owns the one sanctioned append); matches inside `//` / `///` / `/* … */` comments; or a line carrying the explicit opt-out `// wylde-check: unbounded-append-ok` on the same line. The opt-out is for a genuine non-log append (e.g. a resumable-download temp file) and must carry a reason — an uncapped append is the justified exception, never the norm.

**Note — externally-rotated logs:** the Neo4j JVM rotates its *own* `neo4j.log` via a log4j2 `RollingRandomAccessFile` (`Core/Memgraph/vendor/neo4j/conf/user-logs.xml`, 20 MB × 7) written to `server.directories.logs`. Wylde's redirect captures the separate console stdout/stderr into its own `neo4j.log`; that file (only) is bounded by `open_rotating_append` at open time. The two files are distinct — Wylde does not double-manage the JVM's rotated log.
